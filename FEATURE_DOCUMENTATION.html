2. Authentication System
utils/api.ts · store/useAppStore.ts · app/login.tsx
🔑 JWT Token Flow
The app uses a two-token system:
  • Access Token (short-lived) — sent as Bearer header on every request
  • Refresh Token (long-lived) — used silently to get a new access token when it expires (401 response)
  • Both tokens stored securely in expo-secure-store (encrypted device storage)
👤 Login Screen
  • Premium dark gradient UI
  • Accepts any Odoo email + password
  • Shows inline error messages
  • Automatically restores previous session on app launch (no re-login needed)
  • Auto-loads all data after successful login

Login endpoint called

POST /api/v1/auth/token
Body: { "login": "demo", "password": "1234", "device": "SmartHR-Mobile" }

Response: { "access_token": "...", "refresh_token": "...", "expires_in": 3600 }
💡 How to get credentials: Go to Odoo → Settings → Users → click a user → Action → Change Password. Then log in with that user's login name and the new password.

3. Home Screen (Dashboard)
app/(tabs)/index.tsx
🔄 Pull-to-Refresh
Swipe down on the main scroll area to trigger a full data refresh. Calls refreshData() in the store which:
  • Re-fetches all leave requests from /api/v1/leaves
  • Re-fetches attendance records from /api/v1/attendance/<id>
  • Rebuilds notifications from updated leave statuses
  • Updates the clocked-in/out status based on latest attendance
⏱️ Clock In / Clock Out
  • Tapping the button calls POST /api/v1/attendance/check-in or check-out
  • State (active/offline) updates immediately
  • Today's worked hours refresh automatically after each action
  • Prevents double clock-in (Odoo returns 409 if already checked in)
🔔 Notification Center
Tapping the bell icon opens a full bottom sheet panel:
  • Shows a notification for every leave request (approved ✅, refused ❌, pending ⏳)
  • Unread notifications highlighted in blue with a dot indicator
  • Badge number on the bell shows unread count
  • Tap "Mark all read" to dismiss the badge
  • Read state is preserved across data refreshes
⚡ Quick Actions
Three action cards below the clock widget:
  • 📅 Request Time Off → navigates to the Leaves screen
  • 📆 Attendance Calendar → opens the interactive calendar
  • 📈 View Performance → navigates to Performance tab

4. Attendance Calendar
components/CalendarModal.tsx

A fully custom month-grid calendar built with pure React Native — no external library. Opens as a bottom sheet modal from the Home screen.

📆 Calendar Grid
  • Standard month grid (Sun→Sat columns)
  • Navigate between months with ‹ › arrows
  • Today's date highlighted in blue
  • Days with attendance records show colored dots
  • Up to 3 dots per day if multiple records
🎨 Dot Color Legend
● Present  On-time arrival, check-out recorded

● Late arrival  Arrived after expected start time

● Issue  Anomaly detected or missing check-out
🖱️ Tapping a Day — Detail Bottom Sheet
Tapping any marked day opens a second bottom sheet with full attendance detail:
  • Check-in time and Check-out time displayed side by side (e.g. 09:21 → 18:29)
  • Total worked hours (e.g. 8h 15m)
  • Late minutes if flagged (e.g. +21 min) with amber warning
  • Anomaly type if set by Odoo AI anomaly detector (red warning)
  • Missing check-out warning — red banner if no check-out was recorded
  • All clear — green banner for perfect attendance days

Data comes directly from the hr.attendance model via GET /api/v1/attendance/<employee_id>

5. Time Off Screen
app/(tabs)/leaves.tsx
🔄 Pull-to-Refresh
Swipe down on the leaves list to reload all statuses from Odoo. Useful to check if a manager has approved a pending request since you last opened the app.
📅 Leave Calendar
Opens the same calendar component showing each leave request as a colored bar:
  • ● Approved
  • ● Pending
  • ● Refused
Multi-day leaves mark every day in the range.
🗓️ New Request Form — Drum-Style Date Picker
The date input was completely replaced with a native-feeling picker. Instead of typing YYYY-MM-DD manually:
  • Tap the Start Date or End Date field → a bottom sheet date picker opens
  • Three independent drum selectors: Day | Month | Year
  • Tap the up/down arrows to scroll each drum
  • A live preview shows the full formatted date before confirming
  • Tap Confirm Date to apply the selection
  • A X days requested badge auto-calculates the duration

Zero external libraries — built entirely with React Native's built-in TouchableOpacity and Modal.
📤 Submitting a Leave Request
  1. Select Leave Type: Annual (ID 1) / Sick (ID 2) / Personal (ID 4)
  2. Pick Start Date using the date picker
  3. Pick End Date using the date picker
  4. Write a short Reason
  5. Tap Submit to Odoo
  6. The request is created in Odoo as hr.leave with state confirm
  7. The hr_leaves_ai module immediately calculates an AI recommendation
  8. A confirmation alert shows the AI recommendation if one was generated

6. In-App Notification Center
components/NotificationsModal.tsx · store/useAppStore.ts

Since Firebase push notifications require a complex cloud setup, the app implements an in-app notification center instead — a rich panel showing all leave status events.

🔴 Bell Icon Badge
The bell icon in the top-right corner of the Home screen displays a red badge with the count of unread notifications. Updates automatically when data refreshes.
✉️ Notification Types
  • ✅ Approved — leave was validated by manager
  • ❌ Refused — leave was refused by manager
  • ⏳ Pending — leave awaiting manager action
🔄 How Notifications Are Generated
Notifications are built from the live leave request data pulled from Odoo. Every time the app refreshes:
  • Each leave request generates one notification card
  • The read state is preserved across refreshes — a notification you've already seen won't re-appear as unread
  • Tapping the bell opens the panel (unread badge stays until you tap "Mark all read")
  • The panel shows the leave type, date range, and status in plain language

8. Setup & How to Run
Complete step-by-step guide

Step 1 — Start Odoo

cd "C:\Users\nicol\Desktop\stage odoo\Rh_automatise-odoo"
docker compose up -d

Verify Odoo is running at http://localhost:8070

Step 2 — Find your IP address

ipconfig
# Look for: IPv4 Address . . . . . . . 10.41.252.144 (example)

Step 3 — Set the IP in .env

Open smart-hr-mobile/.env and update the IP:

EXPO_PUBLIC_API_BASE_URL=http://10.41.252.144:8070
⚠️ Update this IP every time your computer connects to a different network.

Step 4 — Install dependencies (first time only)

cd "C:\Users\nicol\Desktop\stage odoo\smart-hr-mobile"
npm install

Step 5 — Start the Expo server

npx expo start --tunnel
✅ The --tunnel flag bypasses Windows firewall and Wi-Fi isolation. Your phone can connect even on restricted networks.

Step 6 — Open on your phone

iPhoneOpen Camera app → point at QR code → tap "Open in Expo Go"
AndroidOpen Expo Go app → tap "Scan QR Code" → point at QR code
